Weakness
The volatility eligibility filter does not improve on v1's validation Sharpe, and makes development drawdown meaningfully worse rather than better.

Evidence
Best v2 config (vol_threshold=0.25): dev Sharpe 0.5062, dev max DD -0.3483, val Sharpe 0.4488, val max DD -0.2954. Compare to v1: dev Sharpe 0.4779, dev max DD -0.2757, val Sharpe 0.5424, val max DD -0.2954. Turnover is essentially unchanged (11.06 vs 11.66). The filter neither reduces trading nor improves risk-adjusted return -- it worsens the exact metric (drawdown) it was intended to help, likely because excluding higher-volatility names sometimes removes the strongest-momentum recovery leaders rather than just excluding genuinely erratic ones. Note: the first sweep of this version (before a volume-ratio calculation bug in the reused eligibility code was fixed) produced all-zero results across every configuration; those results were discarded as invalid rather than used as evidence.

Change
Replace the binary volatility eligibility cutoff with volatility-based position sizing: keep v1's existing momentum + dollar-volume eligibility as-is, but weight the selected top-N names inversely to their trailing realized volatility instead of equal-weighting them.

Expected
Should reduce the influence of the most erratic names on portfolio risk without excluding them outright (and losing their momentum information entirely), which is what likely hurt v2 -- downweighting is a softer, less information-destructive intervention than a hard cutoff.

Overfit risk
This is the third and final structural change permitted under the fixed three-version limit; there will be no further version to correct for an unlucky choice of volatility lookback window if this also fails, so the lookback window should reuse the same 126-day period already established in this study rather than introducing a new tunable choice.
